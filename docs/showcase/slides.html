Problem

Interrupted writes make state uncertain

  • Embedded devices must preserve settings and counters across restarts.
  • A partial record can leave an application unsure what data is valid.
  • Recovery needs a rule for deciding which writes to accept.
Users: embedded applications that need a bounded, persistent key-value store.
[PRESENTER]2 / 7
Architecture

One record per fixed-size block

Application → bounded Store → append-only Log → 512-byte Record + CRC → Device (RAM or desktop file)
  • Store and log use generic Read, Write, and Sync operations.
  • Sorted fixed-size table; binary-search lookup.
  • One Put or Delete is one commit, not a multi-operation transaction.
[PRESENTER]3 / 7
Commit and recovery

Sync precedes the table update

Encode → Write block → Sync → Update in-memory table
  • Each record has a sequence number and CRC.
  • On reopen, accept only valid records with the next expected sequence.
  • Replay the accepted prefix to reconstruct the live key-value map.
